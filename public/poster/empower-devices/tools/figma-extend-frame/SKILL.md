# Figma Extend Frame

主流程：读取主视觉的分层构图及可复用组件 → 复用 Variables → 按区域采用 Auto Layout 或构图锚点 → 按 Excel 或对话明确规格生成可编辑画布。保持已有实例与变量绑定关系；无 Excel 时将用户明确的单个或多个规格作为需求清单。

## 输入与工具

先查找对话、当前选择与项目文件中的 Figma 文件/主视觉组件、Variables 集合与模式、Auto Layout 模板以及 Excel 需求表。只询问实际缺失且会阻碍执行的信息。不要默认重新设计主视觉、重建变量体系或生成位图。

读取 Excel 时加载当前环境的 Spreadsheets 技能；通过其支持的工具读取真实工作表、表头与单元格，保留原工作簿。使用可用的 Figma 连接器；每次调用 `use_figma` 前加载当前环境的 `figma:figma-use` 技能，并遵循其 API、字体、页面上下文和错误恢复规则。不要固化插件缓存路径或猜测参数。无法访问表格或写入 Figma 时明确说明受阻部分，不能将计划声称为已生成的画布。

## 1. 读取组件与布局契约

检查源组件、组件集或模板实例的结构及截图，记录：

- 主视觉组件 key/节点 ID、可用 variants、文本/布尔/实例替换属性及其用途。
- 变量集合 ID、变量 ID、类型、模式 ID、绑定属性和别名；使用 ID 区分同名变量。
- Auto Layout 的方向、间距、padding、对齐、固定/自适应/填充尺寸、最小最大尺寸、wrap 与 absolute 子层。
- 不可拉伸的主体、Logo、允许裁切的背景、安全区以及已有横竖版布局变体。

“固定好 Variables”默认表示复用已有配置和绑定；除非用户明确要求，不改全局变量值、不增加集合。每个画布的主题优先通过显式变量模式实现，避免一个画布换肤影响其他画布。组件属性的内容覆盖与变量模式分开映射。

若组件未设好或布局缺少必需规则，先指出具体缺口；在用户已授权的任务范围内做必要补齐。比例改变超出模板适配能力时，采用已有布局变体；没有对应规则时说明推断，不能声称 Auto Layout 能自动决定艺术构图。

## 构图延展与组件边界

先判断原稿是全画布主视觉还是独立内容卡片。全画布主视觉的背景应延续至新画布边缘；人物、产品、界面、云连接、品牌 ribbon paths 等按其层级和锚点参与整幅构图，不默认封装成一个固定比例的整图组件，也不改造成白底加嵌入图片的分区版式。只有本来具有独立复用边界的元素才组件化。

Auto Layout 用于标题组合、CTA、联系信息等具有流式关系的区域。背景、人物、装饰和叠加界面可使用绝对定位、约束和等比缩放；不能为了套用 Auto Layout 改变原稿艺术构图。比例适配前列出原稿可见元素，逐项核对保留或调整；不能未经授权省略 ribbon 等品牌元素。为文字可读性使用与原稿一致的渐隐过渡，而非默认增加纯白信息区。

## 2. 将 Excel 转为产出清单

按 [Excel 映射规则](references/excel-mapping.md) 读取并标准化需求。保留工作表和行号作为来源标识，建立每行到画布的对应关系。

先核对真实表头，再映射宽高、名称、组件/布局变体、变量模式、文案和可见性等字段。仅使用存在的字段；主题等可选字段缺失时继承源模板配置。不要编造默认平台规格。宽高必须明确单位；按像素使用 Figma 尺寸，其他单位需要有依据的转换。

在任务目录保存 `extend-frame-rules.md`，记录组件/变量/布局契约、列映射、目标清单、假设和执行结果。详见 [项目规则结构](references/project-rules.md)。这些是项目数据，不写回全局技能。

## 3. 按行生成画布

默认保留源组件和模板，在空白区域生成结果。对每个有效需求行：

1. 根据表格或对话指定的规格选取已有组件与布局变体，或克隆分层模板；全画布构图保持独立元素关系，记录源与输出 ID。
2. 设置目标画布宽高；保留相关内容的 Auto Layout，通过 FIXED/HUG/FILL、padding、gap 和对齐约束完成布局。先调整容器尺寸，再按正确结构设置尺寸模式，避免 resize 覆盖模式。
3. 将表格内容写入已映射的组件属性，将模式应用到正确变量集合和作用域；保留绑定，不用硬编码值覆盖已有绑定。
4. 等待布局计算后检查结果。主视觉和 Logo 保持比例；文本自然换行，禁止通过无下限缩字号塞入画布。只按授权改写文案。
5. 按原有命名规则或“资源位名 / 宽×高 / 模式”命名，并记录需求行对应的输出节点链接。

先检查一个有代表性的规格，再批量复用；有多类布局时分别验证对应模板。长图按模块与真实内容排布；表格给定固定高度时核对是否容纳内容，不能静默改高或裁掉内容。

不得为适配而默认 detach 实例、栅格化整稿或拉伸产品。需要修改实例内部结构时先选可用 variants、组件属性或嵌套实例替换；确实需脱离组件时说明原因并仅处理必要节点。

## 4. 验收与可恢复执行

检查有效需求行数与输出数一致；逐行核对宽高、名称、组件来源、变量模式、内容覆盖与绑定保留。检查文本溢出、主体变形、裁切、安全区、布局间距及固定高度长图的完整性。

用实际渲染截图检查每类布局的代表稿，以及极端比例和最长文案。发现问题定点修复，并复查受影响的结果。不得仅凭 API 成功宣称视觉通过。

在清单中记录每行状态和已创建节点 ID。失败重试前检查现有结果，续做或修复，避免重复生成；无法完成的行列出具体原因，不静默跳过，也不阻碍无依赖的有效行。

交付 Figma 画布链接、需求行与输出对应清单、预览和未解决问题。只有用户要求时才导出图片或其他文件；原生画布保持可编辑。

## 调用示例

“使用 $figma-extend-frame，基于这个已建好的主视觉组件和 Variables，按 Excel 需求表的每一行，用 Auto Layout 生成对应尺寸的 Figma 画布。”
